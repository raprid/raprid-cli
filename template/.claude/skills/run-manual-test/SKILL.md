# run-manual-test

先に [共通実行ルール](../runtime.md) と
[Gherkin 手順書の規約](../../../docs/feature/README.md) を読む。

`docs/feature/` の手順をエージェントが実行し、結果を
`job/<案件名>/assets/<タスク名>/<実行日>/` に残す。
手順書の正は `.feature` であり、自動実行コードは写しとして扱う。

## 引数

- **タスク名** — 部分一致で探す。省略時は `test:` のある `progress` タスクから選ぶ。
- **シナリオ ID / 章** — 指定時は対象を絞る。省略時は自動実行可能な全シナリオ。

対象が複数に決まらない場合だけ確認する。ブラウザ操作手段がない場合は、前提と対象を整理して
未実施を報告する。人が実機を操作する場合は `verify-task` に切り替える。

## 実行経路

1. `job/<案件名>/assets/e2e/README.md` が存在する場合は、対応する spec・fixture・設定を読み、
   feature との対応範囲を確認してその経路を使う。
2. 案件固有の実行コードがない場合は、利用可能なブラウザ操作・画面取得・ネットワーク確認機能を使う。
3. URL だけを差し替えて、ローカル DB 用 fixture を共有環境や本番へ転用しない。

## 手順

### 1. 対象と前提を確定する

タスクの frontmatter `test:` を読み、ディレクトリ指定は `_` で始まらない `.feature` を
ファイル名順に展開する。

```sh
sed -n '/^---$/,/^---$/p' job/<案件名>/list/<タスク名>.md
find docs/feature/<領域>/<機能> -maxdepth 1 -type f -name '*.feature' | sort
```

`_background.feature` と各章の `Background:` を読み、次を確認する。

- 実行環境、関連リポジトリのブランチと HEAD
- コンテナやサービスの起動状態
- ログインロール、対象データ ID、認証状態
- 変更前の値、操作による影響、復元方法

`@manual` は自動実行から外し、`verify-task` の対象として報告する。
`@destructive` は影響範囲を示して実行前に明示的な確認を取る。

### 2. シナリオを実行する

シナリオごとに Given / When / Then を順番どおり実行する。SQL、API、ブラウザ操作などの
実行手段は手順の記載と対象環境に合わせる。判断できないステップを推測で読み替えない。

操作前後を確認できる証跡を残す。録画機能がある場合はシナリオ単位で GIF または動画を作り、
ファイル名を `<ID>-<内容>.<拡張子>` とする。静止画しか取得できない場合は GIF を作成済みとしない。

### 3. 結果を判定する

Then を実測して、次のいずれかを記録する。

| 判定 | 条件 |
| --- | --- |
| OK | Then がすべて満たされた |
| NG | 期待値と異なる結果を観測した |
| 確認不能 | 必要な画面・値・通信などを確認できなかった |
| 未実施 | 対象外、権限不足、`@manual` などで実行していない |

確認不能や未実施を OK にしない。過去の結果は今回の実行結果と区別する。

### 4. 復元する

今回変更した値と操作を一覧化し、実行前に保存した値へ戻す。共有環境で他者の更新がある場合は
上書きせず報告する。戻したことを再取得して確認し、復元できない対象があればそこで止める。

### 5. 結果を保存する

同日に複数回実行するときは `<実行日>-2/` のように分け、既存結果を上書きしない。

```text
job/<案件名>/assets/<タスク名>/<実行日>/
├── result.md
└── <ID>-<内容>.gif
```

`result.md` には対象手順、実行経路、環境、範囲、ID ごとの結果、証跡、復元状況を書く。
タスクの `## 完了条件` と `## ログ` を今回の結果で更新し、過去ログは残す。

```markdown
# 実行結果 2026-01-15

対象: `docs/feature/admin/item-edit/`
実行: run-manual-test（Playwright）
環境: api `feat/PROJ-123` (abcdef0) / frontend `feat/PROJ-123` (1234567)
範囲: ADM-1-1 〜 ADM-1-3

| ID | 結果 | 証跡 | 備考 |
| --- | --- | --- | --- |
| ADM-1-1 | OK | [gif](ADM-1-1-required-field.gif) | |
| ADM-1-2 | 確認不能 | — | 通信内容を取得できない |

## 環境の復元

| 対象 | 変更内容 | 復元 |
| --- | --- | --- |
| `items` id=100 | `status` draft → active | 初期値に復元済み |
```

最後にシナリオ ID と完了条件の対応を検証する。

```sh
./.claude/skills/verify-task/check_scenario_ids.sh job/<案件名>/list/<タスク名>.md
```

## 中断する条件

- 前提、対象、期待値を一意に決められない
- 同じ操作が繰り返し失敗し、結果を照合できない
- 手順書と画面が食い違い、どちらが正しいか判断できない
- 未承認の破壊的操作や外部送信が必要になった
- 変更前の状態へ復元できない

中断時は成功扱いにせず、実施済みの範囲、観測結果、残った変更を具体的に報告する。
